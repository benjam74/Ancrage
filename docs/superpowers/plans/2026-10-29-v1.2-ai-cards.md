# v1.2 — Cartes générées par IA : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Coller un extrait (notes de formation, chapitre, transcription), obtenir des propositions de notes typées (6 types), les relire, corriger ou écarter, puis ajouter celles retenues.

**Architecture:** `src/core/generate.ts` (pur) construit la demande, le schéma de sortie et convertit la réponse en `NoteFields` validés par `validateFields`. `src/app/ai.ts` appelle Claude via le SDK officiel `@anthropic-ai/sdk` depuis le navigateur, avec la clé API de l'utilisateur. L'interface ajoute un onglet « Générer » dans Créer.

**Tech Stack:** + `@anthropic-ai/sdk` 0.134.0. Modèle `claude-opus-5-5`, sortie structurée (`output_config.format` JSON schema), `effort: medium`, repli serveur sur refus (`fallbacks: "default"`, bêta `server-side-fallback-2026-07-01`).

**Spec:** `docs/specs/2026-10-28-ancrage-v1-design.md` §9 (génération IA v1.2 : clé API locale, avertissement confidentialité) ; réponse utilisateur : « l'IA propose des cartes que tu valides ».

## Global Constraints

- Aucune carte n'entre dans la bibliothèque sans action explicite (Ajouter, Tout ajouter, ou Modifier puis Enregistrer).
- Seules les propositions qui passent `validateFields` sont montrées ; le nombre d'écartées est affiché.
- Notes ajoutées : tag `ia`, source = titre saisi ou « Texte collé ».
- Texte source : 30 000 caractères au plus ; au-delà, refus avec message (pas de troncature silencieuse).
- Clé API stockée localement (`localStorage`), jamais envoyée ailleurs qu'à `api.anthropic.com` ; avertissement : le texte collé est envoyé à Anthropic.
- Erreurs en français : clé refusée, quota, réseau, refus du modèle, réponse tronquée.
- Le contenu généré est en français, fidèle au texte source, sans ajout de connaissances extérieures.

## Review Focus

1. **Réponse partiellement invalide** (un QCM sans distracteur, un type inconnu, un trou vide) : les autres propositions passent, l'écart est compté. → test Task 1.
2. **Refus du modèle ou réponse tronquée** (`stop_reason` `refusal` / `max_tokens`) : message clair, rien d'ajouté. → test Task 2.
3. **Clé absente ou refusée** : aucun appel sans clé ; 401 → « Clé API refusée ». → test Task 2.
4. **Texte trop long ou vide** : refusé avant tout appel. → test Task 1.
5. **Proposition modifiée avant ajout** : c'est la version modifiée qui est enregistrée. → vérif e2e Task 4.

### Task 1: Demande et conversion (cœur)

**Files:** Create `src/core/generate.ts` · Test `tests/core/generate.test.ts`

**Interfaces:**
- `MAX_SOURCE_CHARS = 30_000`
- `interface GenerationRequest { source: string; themeName: string; types: NoteType[]; count: number }`
- `checkRequest(r): string | null` — message d'erreur ou `null`.
- `buildPrompt(r): { system: string; user: string }`
- `OUTPUT_SCHEMA` — objet JSON schema `{ notes: [...] }`, chaque élément avec tous les champs (chaînes et listes, vides si sans objet), `type` en énumération, `rationale` ; `additionalProperties: false`.
- `toProposals(raw: unknown, allowed: NoteType[]): { proposals: { fields: NoteFields; rationale: string }[]; rejected: number }`

- [ ] Tests : `checkRequest` (vide, trop long, aucun type, nombre hors 1–15) ; `buildPrompt` contient thème, types autorisés, nombre, et le texte source dans des balises ; `toProposals` convertit chaque type, écarte type inconnu / non autorisé / invalide et les compte, normalise (rogne, dédoublonne) ; entrée qui n'est pas un objet → 0 proposition.
- [ ] RED puis GREEN ; commit `feat(core): card generation request and conversion`.
