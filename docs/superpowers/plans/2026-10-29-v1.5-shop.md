# v1.5 — Boutique, personnages, parcours animé : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Boutique de 50 objets achetés avec l'XP, 4 personnages en pyjama qui portent les objets, personnage animé sur le parcours.

**Architecture:** Solde dérivé (XP gagnée − achats + reventes) ; achats, reventes, équipements et personnage stockés comme `AppEvent` (déjà synchronisés). Catalogue et règles purs dans `src/core/shop.ts` ; dessins SVG dans `src/data`.

**Tech Stack:** inchangée.

**Spec:** `docs/specs/2026-10-29-v1.5-shop-design.md`.

## Global Constraints

- Paliers et prix : Commun 60–150 (16 objets), Rare 300–600 (16), Épique 1 000–1 800 (12), Légendaire 3 000–6 000 (6).
- Emplacements et effectifs : haut 8, bas 6, chapeau 9, lunettes 5, cou 6, objet 7, compagnon 4, décor 5 (total 50).
- Revente : `Math.floor(prix payé / 2)`.
- Personnages : `renard`, `loutre`, `ourson`, `lapin` ; nom ≤ 20 caractères, rogné ; défaut `renard` / « Renard ».
- Nouvelles cartes rémunérées : 20 par journée d'étude au plus (`XP_NEW_CAP = 20`).
- Aucun objet n'agit sur l'XP, la série ou la planification.

## Review Focus

1. **Solde négatif après fusion de deux appareils** : affiché, achat refusé. → test Task 1.
2. **Objet revendu encore marqué équipé** dans un vieil événement : il n'est plus porté. → test Task 1.
3. **Sauvegarde d'une version future** avec un type d'événement inconnu : lue, événement ignoré. → test Task 2.
4. **Plafond des nouvelles cartes à cheval sur 4 h** (journée d'étude) : compté par journée d'étude. → test Task 2.
5. **Double clic sur Acheter** : un seul achat. → vérif e2e Task 5.
